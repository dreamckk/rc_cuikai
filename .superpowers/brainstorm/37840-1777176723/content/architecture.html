系统架构设计

方案 A：同步网关 + RocketMQ 异步投递

整体数据流

请求生命周期
业务系统
广告/CRM/库存
──POST /notify──▶
Gateway API
接收 + 入队
──publish──▶
RocketMQ
Topic: notify
──consume──▶
Dispatcher
Worker
──HTTP──▶
外部 API
广告/CRM/库存
失败路径： 外部 API 失败 → RocketMQ 自动重试（指数退避）→ 超过最大次数 → 进入 DLQ → 告警 + 人工处理

核心组件职责

Gateway API

接收层

  • Spring Boot REST Controller
  • 验证请求格式（supplier_id 合法）
  • 生成唯一 notification_id
  • 发布到 RocketMQ
  • 返回 202 Accepted（不等投递结果）
Dispatcher Worker

投递层

  • 消费 RocketMQ 消息
  • 按 supplier_id 查询供应商配置
  • 组装 HTTP 请求（URL/Header/Body）
  • 调用外部 API（带超时控制）
  • 成功 ACK，失败不 ACK 触发重试
Supplier Config

配置层

  • DB 表存储供应商信息
  • 字段：id / url / headers / body_template
  • 应用启动时缓存，变更时刷新
Notification Log

审计层

  • DB 表记录每次投递尝试
  • 字段：id / supplier / status / attempts / last_error
  • 用于排查、监控、人工补发

重试策略（RocketMQ 内置）

默认重试次数：16 次，间隔递增（10s → 30s → 1min → 2min → ... → 2h）
超过 16 次后消息自动进入 DLQ（%DLQ%notify），触发监控告警，等待人工处理或手动补发。
